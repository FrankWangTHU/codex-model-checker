旧版代理已从主程序运行路径移除。启动时只执行旧配置恢复，不重启代理；用户需完全重启 Codex 才能清除旧进程缓存的地址。已改动代理项的配置不会被覆盖，备份保留。

抽检只作用于新建子进程；取消/超时仅终止该进程。不会强制重启桌面 Codex。系统 PAC 返回直接连接或不支持的代理类型时，仍可能无法抽检，不能自动切换账号或判为一致。

详见 [直接核验调查](DIRECT-CHECK.md)。

## v0.1.2 桌面响应旁读

本机 Codex Store 26.1013.4894.0 / 后端 0.163.0-alpha.10.2 的真实桌面对话已读取到 `response.model`，并用助手消息 ID 精确匹配当前会话。实测主回答 `gpt-6.1-sol → gpt-6.1-sol`；未将该结果当成 Astra 的桌面实测。Astra 对比、缺失/冲突、重试、分片、轮转和并发另有自动化夹具验证。

直接从 exe 启动与 Store 快捷方式启动可能使用不同日志目录，现同时监听两者。新版本改变 stderr 日志格式或不输出响应时会失去核验能力，不推断模型替换。自动重启只支持本机可发现的 OpenAI.Codex Store 包；需要 Windows 任务计划程序可用。诊断启动和恢复均需用户点击确认，可能中断工作。
