## 尚不能声称已验证的项目

- 未使用用户账号发送真实 ChatGPT / Codex 模型测试请求，也没有为测试切换账户或发起付费 API 请求。
- 用户当前 Codex 桌面版可能使用不会经过 `openai_base_url` 的账户/云端运行路径。配置写入成功或日志中出现 Astra 均不证明已捕获响应。
- ChatGPT 私有协议可能变化。未知 envelope、无法确定的请求关联、缺失字段和超出观察上限的数据都不能显示为“一致”。
- 响应字段由服务器报告；即使字段一致，也无法独立验证实际运行的模型权重。

## 故障处理

| 现象 | 处理 |
| --- | --- |
| 扩展未连接 | 确认桌面后台开启，重新配对，刷新页面；检查端口 43821 是否被占用 |
| 代理就绪但没有流量 | 重启 Codex；确认当前 provider/profile 是否使用该基础地址；不支持的路径保留无法核验 |
| Codex 请求连接本地失败 | 启动 Model Checker 恢复代理服务，或运行 `Codex Model Checker.exe --restore-proxy` 后重启 Codex |
| 配置恢复被拒绝 | 代理项被外部编辑；保留备份，比较原配置，不要删除备份或直接覆盖整个新配置 |
| 请求超大或上游强制压缩 | 代理继续转发，但可能缺少检测字段；无法核验符合预期 |
| 只有模型标签 | 展示标签，无法核验；不会根据标签或回答风格猜测路由 |

## 手工核验

ChatGPT 可以用浏览器开发者工具查看本轮请求里的 `model`，再查看同一请求的响应事件；比较记录详情中的显式路由字段。不要公开包含 Cookie、认证头或对话正文的 HAR 文件。

Codex 应先看到“代理已捕获流量”，并在记录详情中看到网络请求字段和显式响应字段。仅看到“日志监听中”时属于请求侧观察。
